# Контракт новых сообщений (2026-10-20)

Параллельные сессии разрабатывают прошивку и сервер одновременно. Чтобы они сошлись при
слиянии, форматы новых сообщений зафиксированы здесь. Основной протокол: [protocol.md](protocol.md).
Неизвестные `type` и поля получатель молча игнорирует, поэтому порядок выкладки не важен.

## Сервер → колонка

### `task_status`: ход длинной задачи (Claude Code и фоновые агенты)

```json
{"type": "task_status", "state": "working", "label": "Telegram-бот", "pct": 40}
```

- `state`: `idle` (убрать), `working`, `needs_input` (Claude задал вопрос), `needs_permission`
  (ждёт разрешения), `done`, `failed`.
- `label`: до 31 байта UTF-8, что за задача. `pct`: 0..100 или -1 (процент неизвестен).
- Экран: `working`: кольцо прогресса по краю (при -1 бегущая дуга), подпись снизу;
  `needs_input` / `needs_permission`: янтарная пульсация края и метка «Ждёт тебя»;
  `done`: зелёная вспышка, через 4 с гаснет; `failed`: красная. Приоритет ниже звонка и разговора,
  выше часов и сна (сон прерывается на `needs_*`).

### `quiet`: тихий режим

```json
{"type": "quiet", "on": true}
```

Ночной режим уже есть (`night`); `quiet` включает «не слушай»: экран показывает точку и
подпись «Тишина», микрофон колонки не шлёт звук на сервер, пока `on` не станет `false` или не
придёт `listen_start`.

### `light_flash` (необязательно, мост «мама зовёт»)

Не нужен: вспышками света занимается сервер через WLED/HA.

## Колонка → сервер

### `clap`: хлопки

```json
{"type": "clap", "count": 2}
```

Колонка сама распознаёт серию хлопков (на устройстве, без слова пробуждения и без сети).
`count` 2 — переключить весь свет комнаты. Сервер действует по получении.

### `room`: «человек рядом с колонкой»

```json
{"type": "room", "here": true, "rssi": -58, "src": "ble"}
```

Колонка шлёт при смене состояния и раз в 30 с. `src`: `ble` (маячок телефона), `radar`
(датчик присутствия, если будет), `none` (нечем определять). Сервер учитывает это в
`presence.py` как самый сильный признак «в комнате».

## Колонка без сервера

Колонка сама держит часы, таймер и запланированные сигналы, если связи нет. Сервер заранее
присылает `plan` (может повторять при каждом подключении):

```json
{"type": "plan", "alarms": [{"at": 1760940000, "label": "Подъём"}], "timers": []}
```

`at`: Unix-время. Без связи сигнал звучит встроенным тоном и показывается на экране.
