# Навыки Маги: плагины, которые она предлагает и пишет себе сама

Идея: Мага замечает, что чего-то не умеет (или ты говоришь «научись делать X»), предлагает навык, ты соглашаешься,
Claude Code на ноутбуке пишет навык и тесты в отдельной ветке, ты смотришь diff и только потом включаешь.
Ничего не сливается и не выкладывается само.

## Из чего состоит

| Часть | Где | Что делает |
|---|---|---|
| Навык | `server/jarvis/skills/<имя>.py` | модуль с `META`, `TOOLS`, `async def call(name, args, ctx)` |
| Загрузчик | `server/jarvis/skills_loader.py` | находит, проверяет, включает, выключает, перезагружает, изолирует ошибки |
| Предложения | `server/jarvis/skill_requests.py` | `propose_skill`, карточка в Telegram, `/approve`, `/reject`, `/enable`, задание ноутбуку |
| Исполнитель | `server/tools/skill_runner.py` (+ `pc/agent.py`) | на ноутбуке: worktree, `claude -p`, проверки, тесты, коммит в ветке |

В `brain.py` подхват минимальный: `Brain.skills` (загрузчик) добавляет свои функции в `tools()`, а `Brain._call`
сначала спрашивает загрузчик. Образцы: `skills/clock.py` (`current_time`, переехала из `brain.py`) и
`skills/dice.py` (`roll_dice`).

## Формат навыка

```python
META = {"name": "btc", "description": "Курс биткоина", "version": "1.0", "permissions": ["net"]}
TOOLS = [{"name": "btc_price", "description": "...", "parameters": {"type": "OBJECT", "properties": {}}}]

async def call(name, args, ctx):
    data = await ctx.http_get_json("https://api.example.com/price", {"cur": "eur"})
    return {"ok": True, "price": data["eur"]}
```

`META["name"]` совпадает с именем файла (латиница, цифры, `_`). Имена функций не должны совпадать с чужими.
Что есть в `ctx`: `now()`, `log`, `pref/set_pref` (настройки только этого навыка), и по разрешениям:

| Разрешение | Что открывает |
|---|---|
| `net` | `ctx.http_get_json(url, params)`: только https, ответ до 1 МБ, таймаут 10 с; разрешены импорты `urllib`, `http` и т. п. |
| `ha` | `ctx.ha` (объект Home Assistant) |
| `google` | `ctx.google` |
| `files` | `ctx.read_text/write_text` только в `data/skills/<имя>/`, файл до 200 КБ |

Без разрешения соответствующего поля в `ctx` нет (`None`) или метод бросает `PermissionError`.

## Жизненный цикл

1. **Предложение.** Gemini вызывает `propose_skill(title, what, why)`. Запись в `brain.db` (`skill_requests`, статус
   `proposed`), карточка в Telegram: «Предлагаю навык: … Согласен? /approve N или /reject N». Не больше 5
   нерешённых предложений, повтор того же названия новую карточку не создаёт.
2. **Решение.** `/approve N` или `/reject N` в Telegram, либо голосом «да, делай» (Gemini вызывает
   `skill_decision`; номер не нужен, если ждёт одно предложение). `/skills` показывает навыки и предложения.
3. **Исполнение.** Одобрение отправляет ноутбуку `skill_job` через мост ПК (`/pc`). Если ноутбук не на связи,
   задание ждёт и уйдёт, как только `pc/agent.py` подключится.
4. **Результат.** `skill_result`: ветка `skill/<имя>`, список файлов, diff, итог тестов. В Telegram приходит
   «навык готов: смотри diff» (`/diff N` показывает diff целиком, до 6000 знаков).
5. **Включение.** Ты сам: `git diff main...skill/<имя>`, слить ветку, выложить сервер, потом `/enable <имя>`.
   Пока файла на сервере нет, `/enable` честно отвечает, что навыка нет в папке. Голосом включить навык можно
   только прямой просьбой «включи навык …» (функция `skills_manage`).

Управление навыками (Telegram и консоль): `skills` (список), `skills enable|disable <имя>`, `skills reload [имя]`,
`/diff N`. Голосом: «перезагрузи навыки», «выключи навык …» (функция `skills_manage`).

## Модель безопасности

Главный принцип: код навыка попадает на сервер только через ветку, которую читает человек, и включается только
по явному «да». Остальное — слои, которые уменьшают вред от ошибки или подвоха.

**Что навык может.** Отвечать на вызовы Gemini; читать время; ходить по https туда, куда ему разрешено `net`
(сервер не фильтрует адреса, смотри diff: куда именно ходит навык); читать и писать свою папку при `files`;
говорить с Home Assistant и Google при `ha`/`google` (с теми же правами, что у самой Маги: поэтому такие
навыки читай внимательнее всего).

**Чего навык не может (проверяется до запуска).** `check_source` разбирает код и отклоняет: импорты `os`, `sys`,
`subprocess`, `socket`, `ctypes`, `shutil`, `importlib`, `pickle`, `threading`, `inspect`, `types` и прочее
опасное; сетевые модули без `net`; `pathlib`/`io` без `files`; `open()`, `eval`, `exec`, `compile`,
`__import__`, `getattr/setattr`, доступ к `__class__`, `__globals__`, `__subclasses__` и подобным; импорт `jarvis`
(всё нужное в `ctx`). Нарушение — навык не загружается, ты получаешь сообщение.

**Честное ограничение.** Это не песочница. Навык выполняется в процессе сервера, статическая проверка ловит очевидное,
но не защищает от изощрённого обхода. Поэтому главная защита — просмотр diff человеком и то, что включение
ручное. Для действительно недоверенного кода нужен отдельный процесс (в планах, если навыков станет много).

**Изоляция сбоев.** Исключение или зависание (20 с) в `call` не роняют разговор: навык отключается, в Telegram идёт
сообщение «навык … отключён: причина», Gemini получает `{"ok": false, "error": …}`. `skills reload <имя>` пробует
снова после исправления.

**Подмена файла.** При включении в базу пишется sha256 файла. Если файл изменился, а ты не включал заново, при
старте сервера он не загружается (кроме доверенных `clock` и `dice`, лежащих в репозитории с начала). Явная
`skills reload` принимает новую версию.

**Откат.** `skills disable <имя>` (мгновенно, без перезапуска), удалить файл и `skills reload`, либо
`git revert` слияния и новая выкладка. Состояние включения лежит в `brain.db` (таблица `skills`).

**Исполнитель на ноутбуке** (`tools/skill_runner.py`):
- работает в отдельном git worktree `.claude/worktrees/skill-<имя>` на новой ветке `skill/<имя>` от текущего
  коммита; основная ветка и рабочая папка не трогаются; ветка с таким именем уже есть — отказ;
- Claude Code запускается так: `claude -p … --permission-mode dontAsk --permission-prompts none --tools
  Read,Glob,Grep,Edit,Write,Bash --allowedTools Read Glob Grep "Edit(<файл навыка>)" "Edit(<файл теста>)"
  "Bash(python -m pytest -q <файл теста>)" --max-turns 30 --max-budget-usd 3.00 --no-session-persistence`.
  Нет веба, нет субагентов, любое действие вне белого списка отклоняется без вопросов. Правило `Edit(путь)`
  покрывает и Write (документация Claude Code, раздел Permissions). Правила пользователя из `~/.claude/settings.json`
  всё равно действуют: если там широкие разрешения, они остаются;
- лимиты: 30 ходов, 3 доллара (клиентская оценка), 20 минут на стене (по таймауту процесс убивается вместе с детьми);
  меняются в `SkillRunner(...)`;
- окружение без секретов: переменные с `TOKEN`, `SECRET`, `PASSWORD`, `API_KEY`, `REFRESH` вырезаются (кроме
  `ANTHROPIC_*` и `CLAUDE_*`, они нужны самому Claude Code);
- после запуска: `git status` должен показать только два файла (`server/jarvis/skills/<имя>.py` и
  `server/tests/skills/test_<имя>.py`); любой другой изменённый файл — отказ без коммита; затем та же проверка
  `check_source`; затем `pytest` на тест навыка; только после этого коммит в ветке;
- **не делает** `push`, `merge`, `checkout`, не выкладывает, не трогает сервер и колонку.
- текст задания (из слов Gemini) в подсказке помечен как описание навыка, а не как команды Claude; даже если в нём
  подвох, права Claude Code ограничены двумя файлами, а результат читает человек.

Тесты навыка из `server/tests/skills/` лежат в ветке навыка и после слияния запускаются вместе со всеми
(`python -m pytest -q`).

## Настройка ноутбука

- Установлен Claude Code (`claude` в PATH) и выполнен вход.
- Запущена `pc/agent.py` (она же слушает `skill_job`); репозиторий на ноутбуке `C:\dev\jarvis` с `server/.venv`.
- Базовая ревизия — текущий `HEAD` основного репозитория. Хочешь от другой ветки, переключи её перед одобрением.
- Ручной запуск без сервера: `server\.venv\Scripts\python server\tools\skill_runner.py job.json`, где в
  `job.json` поля `id`, `name`, `title`, `what`, `why`.

## Протокол (сервер ↔ ноутбук)

Неизвестные типы получатель игнорирует, как везде.

```json
{"type": "skill_job", "id": 3, "name": "btc", "title": "Курс биткоина", "what": "...", "why": "..."}
{"type": "skill_progress", "id": 3, "text": "Claude Code пишет навык"}
{"type": "skill_result", "id": 3, "ok": true, "branch": "skill/btc", "files": ["..."], "diffstat": "...",
 "diff": "первые 3000 знаков", "tests": "3 passed", "cost": 0.42, "seconds": 210}
{"type": "skill_result", "id": 3, "ok": false, "error": "тесты не прошли: 1 failed"}
```

Статусы в `skill_requests`: `proposed` → `approved` → `running` → `ready` → `enabled`; ещё `rejected`, `failed`.
